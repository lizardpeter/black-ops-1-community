# Windows x64 migration

The verified builds target Win32. The experimental `enhanced-x64` preset compiles the full enhanced multiplayer target with the x64 toolchain while the port is in progress.

```powershell
cmake --preset enhanced-x64
cmake --build --preset enhanced-x64-release
```

This preset uses the June 2010 DirectX SDK's x64 libraries and the bundled x64 NVAPI library. Pass `-DBO1_X64_VPX_LIBRARY=C:/path/to/libvpx.lib` at configure time to provide a static x64 archive built for the bundled VPX headers. Without that archive the x64 build omits VP8 recording and retains the existing MJPEG path.

| Boundary | What the pinned source does | x64 migration |
| --- | --- | --- |
| Fastfile structs and relocations | `Load_RawFile` reads 12 bytes into a native struct with two pointers. `DB_ConvertOffsetToPointer` overwrites a 32-bit encoded field with a native address. Alias fixups read 32 bits from the stream block. | Keep the original 32-bit serialized layout, decode references separately, and resolve into native storage. Port one asset family at a time and verify against an x86 load. |
| Platform code | `win_shared.cpp` used x87 inline assembly for vector snapping. `win_configure.cpp` has disabled x86 CPUID code. | The enhanced x64 build now uses the engine’s existing SSE rounding helper for vector snapping. |
| Engine layouts | Pointer-bearing asset, material, font, and render command layouts assert 32-bit sizes. Code also uses hard-coded offsets and pointer-to-integer casts. | Keep serialized and protocol structures fixed-width. Replace hard-coded runtime offsets with typed members where the layout changes. |
| Dependencies | The linker selects Win32 Bink, Steam, libvpx, and NVIDIA libraries and the SDK x86 library path. | The enhanced target excludes the Steam, Bink, and XInput imports. VP8 recording is available when an x64 static archive is supplied. The initial x64 build retains D3D9. |

The first x64 target in `enhanced/port/x64` tests the packed fastfile reference format and resolves a reference to a full-width native address. It follows the seven-block layout in `db_registry.h` and the one-based offset encoding in `db_stream_load.cpp`. The existing loader still owns alias fixups and asset loading. The first end-to-end asset-loader target is `RawFile`, including inline data, alias resolution, and a byte-for-byte payload comparison with x86.

The standalone target now also decodes a 12-byte `RawFile` header into native views, including inline names, block-backed names, and binary payloads. Synthetic tests check payload bytes and stream advancement. Asset registration, `Load_RawFilePtr` alias fixups, and comparison against an x86 load of retail game data are pending. See [runtime DLL dependencies](runtime-dlls.md) for the vendor-library migration.
